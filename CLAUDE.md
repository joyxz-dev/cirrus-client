# Cirrus — CLAUDE.md

## What This Is
A Minecraft launcher. Tauri v2 (Rust) + SvelteKit + Tailwind CSS.
Binary name: `cirrus`. App ID: `gg.cirrusclient.app`.

## Hard Rules
1. No ads, banners, or sponsored content inside the app — ever.
2. No upsell buttons, premium badges, or nag screens — ever.
3. No telemetry or analytics without explicit user opt-in.
4. No unnecessary dependencies. Every crate/package must earn its place.
5. **Security is non-negotiable.** Tokens are never logged, never stored in plaintext, never sent to the frontend beyond username/UUID. Any shortcut here is a critical bug.
6. Flag and ask before building anything that violates rules 1–5.

## Security Architecture

This is the highest-priority section. Read it fully before touching auth or storage.

### Token Storage
- The MSA `refresh_token` is the only credential persisted to disk.
- It is stored via `tauri-plugin-store` with OS-level encryption. On Windows this uses DPAPI, on macOS the Keychain, on Linux libsecret. Never store it as plaintext JSON.
- Access tokens (MSA, XBL, XSTS, Minecraft) are derived at runtime and held in memory only. They are never written to disk, never logged, never included in error messages.
- Tokens are zeroized from memory after use using the `zeroize` crate.

### What the Frontend Never Receives
The frontend (SvelteKit) only ever receives:
- `username: String`
- `uuid: String`
- `expiresAt: u64` (for UI refresh prompting only)

No access token, no refresh token, no raw API response ever crosses the Tauri IPC boundary to the frontend. Commands return structured data only.

### Network Security
- All requests to Microsoft, Mojang, Xbox, and Modrinth endpoints use HTTPS. Never downgrade.
- `reqwest` must be built with `native-tls` or `rustls`. Verify TLS is not disabled anywhere.
- Certificate pinning is not required but TLS errors must never be silently swallowed.
- The Azure client ID is a public client (no secret). It lives in `.env`, gitignored, injected at build time via Tauri's build script. Never hardcode it in source.

### Asset Integrity
- Every file downloaded from Mojang is SHA1-verified before use.
- Every mod downloaded from Modrinth is SHA512-verified before installation.
- Files that fail verification are deleted and the error is surfaced to the user — never silently used.
- Do not trust a file's existing presence on disk without re-verifying its hash.

### IPC Boundary Rules
- Tauri commands expose the minimum surface area needed. No catch-all commands.
- Never deserialize raw user input directly into a filesystem path. Sanitize and validate all paths.
- Instance IDs are UUIDs generated by the backend. Never accept a raw path from the frontend as an instance reference.
- All file operations are scoped to the Cirrus data directory. Reject any path that resolves outside it.

### Auth Flow Security
- Use the device code flow (not implicit). No tokens in URLs, ever.
- Re-authentication on token expiry must happen silently in the background via refresh token. Never ask the user to log in again unless the refresh token itself has expired or been revoked.
- On logout, zeroize the refresh token from memory and delete it from the store.
- On account deletion, purge all associated stored credentials immediately.

### Dependency Security
- Run `cargo audit` before every release. Fail the build on any high/critical CVE.
- Pin dependency versions in `Cargo.lock`. Do not use `*` version specifiers.
- Minimize the dependency tree. Each crate added is an attack surface added.

### Additional Crates Required for Security
```toml
zeroize = { version = "1", features = ["derive"] }   # zero tokens from memory
```

## Isolated Instance Folders

Every instance is fully self-contained. Instances never share a game directory.

### Directory Layout (per instance)

```
{cirrus_data_dir}/
├── instances/
│   └── {instance-uuid}/
│       ├── instance.json        # instance metadata (name, version, loader, settings)
│       ├── mods/                # installed mods (.jar files)
│       ├── resourcepacks/       # texture packs — instance-specific
│       ├── shaderpacks/         # shaders — instance-specific
│       ├── saves/               # worlds — instance-specific
│       ├── servers.dat          # server list — instance-specific
│       ├── screenshots/         # instance-specific
│       ├── logs/                # instance-specific
│       ├── config/              # mod configs — instance-specific
│       └── options.txt          # game settings (may be symlinked if sync is on)
├── assets/                      # shared Mojang assets (all instances share this)
├── libraries/                   # shared Mojang libraries (all instances share this)
├── java/                        # managed Java installs (shared)
├── settings/
│   └── global_options.txt       # the shared options.txt used when sync is enabled
└── cirrus.json                  # global app config
```

### Assets and Libraries Are Shared
`assets/` and `libraries/` are shared across all instances to save disk space. These are read-only during gameplay and safe to share. Instance game directories are the only thing that is isolated.

### options.txt Sync

Settings sync (`options.txt`) is **on by default**. Behavior:

- When sync is enabled: `{instance}/options.txt` is a **symlink** pointing to `{cirrus_data_dir}/settings/global_options.txt`.
- When sync is disabled: the symlink is replaced with a real copy of the file, and changes only affect that instance.
- On instance creation: if sync is on, create the symlink. If `global_options.txt` doesn't exist yet, create it from Minecraft's defaults.
- On sync toggle (on → off): copy the current `global_options.txt` into the instance as a real file, remove the symlink.
- On sync toggle (off → on): delete the instance's `options.txt`, create the symlink. Warn the user that instance-specific settings will be replaced.
- On Windows: use junction points or actual symlinks (requires developer mode or admin). Handle the fallback gracefully — if symlinks aren't available, copy on launch and write back on close.

This must be implemented in Rust in `instance/sync.rs`.

### Instance Metadata (instance.json)
```json
{
  "id": "uuid-v4",
  "name": "My Fabric Instance",
  "mcVersion": "1.21.4",
  "loader": "fabric",
  "loaderVersion": "0.16.0",
  "allocatedRamMb": 4096,
  "syncOptions": true,
  "jvmArgs": [],
  "resolution": { "width": 1920, "height": 1080 },
  "createdAt": 1700000000000,
  "lastPlayedAt": null,
  "iconPath": null
}
```

### Launch Directory Flag
When launching, pass `-Dminecraft.applet.TargetDirectory` and `--gameDir` pointing to the instance directory, not `.minecraft`. This is what tells Minecraft to use the isolated folder.

```rust
// In launch.rs, when building JVM args:
args.push(format!("--gameDir={}", instance_dir.display()));
```

## Error Handling

```rust
#[derive(thiserror::Error, Debug)]
pub enum CirrusError {
    #[error("Network: {0}")] Network(#[from] reqwest::Error),
    #[error("IO: {0}")] Io(#[from] std::io::Error),
    #[error("JSON: {0}")] Json(#[from] serde_json::Error),
    #[error("Auth: {0}")] Auth(String),
    #[error("Instance: {0}")] Instance(String),
    #[error("Launch: {0}")] Launch(String),
    #[error("Security: {0}")] Security(String),
}

impl serde::Serialize for CirrusError {
    fn serialize<S>(&self, s: S) -> Result<S::Ok, S::Error>
    where S: serde::Serializer {
        s.serialize_str(self.to_string().as_ref())
    }
}
```

Never include token values, file paths outside the data directory, or raw system errors in messages returned to the frontend.

## Frontend Invoke Pattern

Never call `invoke()` from components. All calls through `src/lib/tauri.ts`:

```typescript
import { invoke } from '@tauri-apps/api/core';

export const commands = {
  startAuth: () => invoke<Account>('start_auth'),
  listInstances: () => invoke<Instance[]>('list_instances'),
  launchInstance: (id: string) => invoke<void>('launch_instance', { id }),
  searchMods: (q: ModSearchQuery) => invoke<ModSearchResult>('search_mods', { query: q }),
  setSyncOptions: (id: string, enabled: boolean) =>
    invoke<void>('set_sync_options', { instanceId: id, enabled }),
};
```

## External APIs

### Mojang
- Manifest: `https://launchermeta.mojang.com/mc/game/version_manifest_v2.json`
- Assets: `https://resources.download.minecraft.net/{hash[0:2]}/{hash}`
- SHA1 verify every file. Skip if hash matches. Delete and error if hash fails.

### Microsoft Auth (exact sequence)
1. `POST https://login.microsoftonline.com/consumers/oauth2/v2.0/devicecode`
   scope: `XboxLive.signin offline_access` — show `user_code` + `verification_uri` to user
2. Poll `POST .../token` every 5s until `authorization_pending` clears
3. `POST https://user.auth.xboxlive.com/user/authenticate` — get XBL token + user hash
4. `POST https://xsts.auth.xboxlive.com/xsts/authorize` — RelyingParty: `rp://api.minecraftservices.com/`
5. `POST https://api.minecraftservices.com/authentication/login_with_xbox` — get MC access token
6. `GET https://api.minecraftservices.com/minecraft/profile` — get UUID + username

Persist only: MSA `refresh_token` (encrypted via tauri-plugin-store).
Hold in memory only: MSA access token, XBL token, XSTS token, MC access token.
Zeroize all in-memory tokens after use with the `zeroize` crate.

### Modrinth
Base: `https://api.modrinth.com/v2`
Header: `User-Agent: Cirrus/0.0.1 (cirrusclient.gg)` — always.

```
GET /search?query=&facets=[["project_type:mod"]]&index=relevance&offset=0&limit=20
GET /project/{id|slug}/version?loaders=["fabric"]&game_versions=["1.21.4"]
GET /version/{id}   # files[].url + files[].hashes.sha512
```

SHA512 verify every mod after download. Delete and error on mismatch.

## Build Order

**Phase 1 — Foundation**
Scaffold → app shell → Microsoft auth (with full security model) → encrypted token storage → home screen

**Phase 2 — Instances & Launch**
Version manifest → isolated instance directory creation → instance metadata → asset download + SHA1 verify → options.txt sync (symlink, on by default) → JVM launch with `--gameDir` → launch state machine + progress bar

**Phase 3 — Mod Browser**
Modrinth search → mod browser UI → version selector → download + SHA512 verify + install → per-instance mod list

**Phase 4 — Polish**
Settings (RAM, Java, resolution, sync toggle) → multiple accounts → error UI → About screen only

## Git Version Control

### This Is Required, Not Optional
Commit to Git constantly throughout development. Every meaningful unit of work — a working function, a passing test, a completed UI component — gets its own commit before moving on. Do not batch hours of work into one commit. If something breaks, you need to pinpoint exactly where.

### Commit Cadence
- Commit **every time something works** that didn't work before.
- Commit **before refactoring** anything — always have a clean rollback point.
- Commit **before starting a new feature** — preserve the current working state.
- Commit **at the end of every session** — never leave the repo dirty overnight.
- If in doubt: commit. A commit costs nothing. Lost work costs hours.

### Commit Message Format
Imperative present tense. One line. Specific.

```
Add Microsoft device code auth flow
Implement SHA1 verification for asset downloads
Wire launch button to selected instance store
Fix options.txt symlink fallback on Windows
Add per-instance resourcepacks directory on creation
```

Not: `stuff`, `fix`, `wip`, `updates`, `working now`, `changes`.

### Branch Strategy
```
main          # always stable and buildable
feature/      # new features (e.g. feature/mod-browser)
fix/          # bug fixes (e.g. fix/symlink-windows)
chore/        # maintenance (e.g. chore/update-deps)
```
